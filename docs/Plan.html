01 · ANÁLISIS DEL PROYECTO

¿Qué es LUMEN ST?

Un FPS cooperativo P2P construido en un único archivo HTML con Three.js r128, PeerJS y Web Audio API. Ambientado en una estación de metro en loop sellado, combina supervivencia por oleadas, reanimación de compañeros, bots IA, chat de texto/voz PTT y conectividad WAN vía Metered TURN.

THREE.JS r128 PEERJS 1.4.7 WEBRTC METERED TURN WEB AUDIO API POINTER LOCK API CANVAS 2D INSTANCED MESH PMREM / IBL OBJECT POOLING
✓

FORTALEZAS ACTUALES

Arquitectura P2P resiliente con fallback TURN, sistema de pools de objetos (60 zombies, 8 rocas), LOD dinámico, frustum culling, InstancedMesh para draw calls, audio procedural Web Audio, y UI táctil ergonómica.

ARQUITECTURASÓLIDA
⚠

DEUDAS TÉCNICAS

~4.200 líneas en un solo archivo IIFE, variables globales (window.ammoCrates, window.zombieHitboxes), sin módulos ES6, sin tree-shaking, sin build step, CDN con fallbacks múltiples, sin tests automatizados.

MANTENIBILIDADCRÍTICA
⚡

OPORTUNIDADES

Migración a ES Modules + Vite, Web Workers para IA, OffscreenCanvas para minimap, ECS (Entity Component System) para zombies, state management centralizado, asset pipeline con compresión WebP/KTX2.

CRECIMIENTOALTO
◉

RIESGOS

Three.js r128 desactualizado (2021), PeerJS sin actualizaciones mayores, API keys de Metered expuestas en cliente, sin rate-limiting en red, sin validación anti-cheat, sin persistencia de progreso.

02 · PLAN DE MEJORA

5 FASES DE OPTIMIZACIÓN

Plan incremental no destructivo: cada fase es independiente, puede desplegarse por separado y mantiene el 100% del contenido original. Priorizado por impacto/effort ratio.

01

RENDIMIENTO & GPU (Quick Wins)

PRIORIDAD ALTA ⏱ 3-5 DÍAS 📈 +40% FPS ESPERADO
P1 · CRÍTICO

Técnicas a aplicar

  • Occlusion Culling con THREE.Octree para ocultar sectores tras paredes (actualmente solo frustum culling)
  • Geometry Merging: fusionar geometría estática de vías, traviesas y rieles en BufferGeometryUtils.mergeGeometries() → reducir draw calls de ~40 a ~4
  • Texture Atlasing: consolidar las 4 texturas HD (tile, conc, steel, floor) en un atlas 2048×2048 con UV remapping
  • Shadow Cascades: limitar shadowMap a 512×512 en móvil, 1024 en desktop. Desactivar sombras en zombies lejanos (>15m)
  • LOD agresivo: añadir nivel LOD3 a 40m (billboard sprite) y LOD4 a 60m (ocultar)
  • Pixel Ratio Dinámico: renderer.setPixelRatio() ajustado según FPS (bajar a 0.75x si <45fps)

Implementación técnica

  • Implementar requestIdleCallback para tareas no-críticas (carga de texturas HD, build de steam)
  • Usar renderer.info.render.calls como telemetry en el FPS counter
  • Activar renderer.autoClear = false con clear manual por capas
  • Implementar async texture decoding con createImageBitmap() en vez de new Image()
  • Pool de Vector3 reutilizables (actualmente hay ~20 allocaciones/frame en updateZombies)
  • Reemplazar Math.random() por XorShift128 PRNG (10x más rápido, determinista para red)
02

ARQUITECTURA & CODE SPLITTING

PRIORIDAD ALTA ⏱ 7-10 DÍAS 📈 MANTENIBILIDAD x5
P1 · CRÍTICO

Estructura modular propuesta

  • Migrar a Vite + ES Modules manteniendo el HTML como entry point
  • Separar en módulos: core/, entities/, systems/, net/, ui/, audio/
  • Implementar patrón ECS (Entity Component System) con bitecs o miniplex para zombies/bots
  • Centralizar estado en store reactivo (Zustand-like) para HP, ammo, wave, playerState
  • Eliminar variables globales: window.ammoCrates, window.zombieHitboxes → encapsular en módulos
  • Añadir TypeScript progresivo (JSDoc → TS migration) para tipar interfaces de red

Code splitting & loading

  • Lazy-load del módulo P2P solo cuando se crea/une sala (import('./net/peer.js'))
  • Code-split texturas HD: cargar solo las del sector actual
  • Implementar Service Worker para cache offline del core (Three.js, PeerJS)
  • Tree-shake Three.js: importar solo three/core, three/lights, etc.
  • Bundle target: <500KB gzip (actualmente ~180KB sin libs, ~700KB con Three.js)
  • Implementar feature flags para activar/desactivar sistemas (bots, chat, PTT)
03

NETWORKING & ANTICHEAT

PRIORIDAD MEDIA ⏱ 5-7 DÍAS 📈 SEGURIDAD x10
P2 · IMPORTANTE

Mejoras de red

  • Server-Authoritative: el host valida posiciones, daños y kills (actualmente client-authoritative)
  • Implementar delta compression: enviar solo cambios de estado, no estado completo
  • Rate limiting: máximo 30 msg/s por peer, con token bucket
  • Snapshot interpolation con buffer de 100ms para suavizar remotos
  • Client-side prediction + server reconciliation para movimiento local
  • Implementar interest management: solo enviar datos de zombies en radio de 50m

Seguridad

  • Mover API key de Metered a backend proxy (Cloudflare Worker, 50 líneas)
  • Firmar paquetes críticos con HMAC (daño, kills, wave start)
  • Validar cooldowns de disparo en host (anti-autoaim, anti-rapidfire)
  • Validar speed hack: comparar distancia recorrida vs tiempo transcurrido
  • Implementar replay validation para headshots sospechosos
  • Añadir ban list persistida en localStorage + reporte al host
04

VISUAL & AUDIO POLISH

PRIORIDAD MEDIA ⏱ 4-6 DÍAS 📈 +25% INMERSIÓN

Mejoras visuales

  • Music system: stems adaptativos que intensifican con oleadas
  • Dolby Atmos binaural para auriculares (HRTF ya soportado por Web Audio)

04 · RECOMENDACIONES FINALES

VEREDICTO PROFESIONAL

Recomendaciones priorizadas por impacto inmediato, ordenadas de mayor a menor urgencia.

01 Migrar a Vite + ES Modules

El cambio más transformador. Reduce bundle 40%, habilita tree-shaking, hot-reload para desarrollo, y prepara el código para escalar. Mantén el HTML como entry; solo separa el JS en módulos. Impacto inmediato en TTI y mantenibilidad.

ARQUITECTURA · SEMANA 1

02 Object Pooling Universal

Ya tienes pools para zombies y rocas. Extiende el patrón a partículas, trazadores, impactos, pickups, bots. Elimina 100% de GC pauses. Usa THREE.Object3D reutilizables con .visible toggle en vez de new/add/remove.

PERFORMANCE · SEMANA 1-2

03 Web Workers para IA

Mueve updateZombies(), updateBots() y pathfinding a un Web Worker. Libera el main thread para render. Comunicación vía postMessage con transferables. Gain esperado: +15-20 FPS en oleadas densas.

PERFORMANCE · SEMANA 2

04 Server-Authoritative Networking

El host debe validar TODO: daño, posición, kills. Implementa checksum de estado cada 5s. Añade rate-limit (30 msg/s) y validación de cooldown de disparo. Previene 95% de trampas básicas sin backend dedicado.

SEGURIDAD · SEMANA 3

05 Mover API Keys a Backend

La API key de Metered está expuesta en cliente. Crea un Cloudflare Worker de 50 líneas que proxy las credenciales TURN. Coste: $0/mes hasta 100K requests. Previene abuso de tu cuota de relay.

SEGURIDAD · SEMANA 3

06 Actualizar Three.js a r165+

r128 es de 2021. Pierdes WebGPU backend, mejoras de 40% en renderer, y nuevos features como BatchedMesh (reduce draw calls 10x). Migration guide oficial disponible. Testea en rama three-upgrade.

MODERNIZACIÓN · SEMANA 4

07 GPU Particles con Shaders

Migrar polvo, vapor, sangre y chispas a ShaderMaterial con simulación en vertex shader. Reduce CPU 70% para partículas. Usa InstancedBufferGeometry para 10K partículas a 60 FPS en móvil.

VISUAL · SEMANA 4-5

08 Audio 3D Espacial

Implementa PannerNode con HRTF para todos los sonidos de zombies. Añade ConvolverNode con IR de túnel real para reverb. Gain: +40% inmersión, especialmente con auriculares. Soportado en todos los browsers modernos.

AUDIO · SEMANA 5

09 Testing Automatizado

Añade Vitest para unidades (sistemas de daño, red, pools) y Playwright para E2E (lobby → gameplay → gameover). Coverage objetivo: 70% en módulos críticos (net, combat). Previene regresiones en cada deploy.

CALIDAD · SEMANA 6

10 Analytics & Telemetry

Instrumenta con Plausible (privacy-first) o self-hosted. Mide: session length, wave reached, weapon usage, death causes, P2P success rate. Datos reales para priorizar features. Evita decisiones por intuición.

PRODUCTO · SEMANA 6-7

11 PWA + Offline Mode

Convierte en Progressive Web App: manifest.json, service worker, installable. Cachea Three.js + PeerJS + assets. Permite jugar solo offline. Gain: +30% retención móvil, aparece en home screen como app nativa.

DISTRIBUCIÓN · SEMANA 7

12 Documentación & Onboarding

Genera JSDoc automático con TypeDoc. Crea README con arquitectura, diagramas (Mermaid), y guía de contribución. Añade tutorial in-game para primeros 2 minutos. Reduce churn de nuevos jugadores 50%.

UX · SEMANA 8
7.2 PUNTUACIÓN GLOBAL

CONCLUSIÓN EJECUTIVA

LUMEN ST es un proyecto técnicamente ambicioso que demuestra dominio avanzado de WebGL, P2P y audio procedural en un único archivo. La arquitectura P2P con Metered TURN es profesional, el sistema de pools y LOD muestra pensamiento en performance, y la UI táctil es ergonómica. Sin embargo, la deuda técnica (archivo monolítico, globals, sin tests) y las debilidades de seguridad (API keys expuestas, client-authoritative) limitan su escalabilidad.

Las 5 fases propuestas son incrementales y no destructivas. Si implementas solo Fase 1 y 2 (2-3 semanas), obtendrás +50% FPS, -50% bundle, y mantenibilidad profesional. El juego tiene potencial comercial real como web game cooperativo, especialmente con la tendencia de .io games y browser FPS.

Recomendación final: Prioriza Fases 1→2→3 en ese orden. No toques gameplay (Fase 5) hasta tener arquitectura sólida. El código actual es un MVP impresionante; con estas optimizaciones, se convierte en producto.
